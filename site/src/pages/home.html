Completely local

Your documents never leave the device

Free PDF SDK is a WebAssembly app that runs inside your page, in an iframe on your own origin. Opening, rendering, annotating, editing, redacting and saving all happen in the user's browser. There is no Free PDF SDK server to send anything to.

The user's device
Your page PDF viewer · WebAssembly Your code
Free PDF SDK servers: none

  • No server

    Nothing to run but static files: the viewer is a folder of HTML, JavaScript and WebAssembly that your site serves.

  • No uploads

    PDFs open in browser memory. A saved PDF or exported comments are handed to your code, never posted anywhere.

  • No telemetry

    The SDK makes no network requests of its own: no analytics, no licence checks, no phoning home. It loads its own files and any PDF URL you give it.

  • Passwords stay local

    Encrypted PDFs are decrypted in the browser. Passwords and document contents are never sent anywhere.

The one way out is the user's choice: a web link inside a document opens only after the user agrees, and ui: { externalLinks: false } turns those links off.

    Integrations

    A PDF viewer for React, Vue, Angular, Svelte and plain JavaScript

    First-class components for React and Vue, an action for Svelte, and a Web Component for Angular and everything else, including plain JavaScript. One npm package, fully typed.

    tsx
    
import { useRef } from "react";
import { FreePdfViewer, type FreePdfViewerHandle } from "@mecorelabs/free-pdf-sdk/react";

export function ProofReview({ url }: { url: string }) {
  const ref = useRef<FreePdfViewerHandle>(null);
  return (
    <FreePdfViewer
      ref={ref}
      baseUrl="/free-pdf-sdk/"
      mode="annotate"
      features={{ stamps: false }}
      document={{ url }}
      onAnnotationsChanged={async () => {
        const xfdf = await ref.current?.viewer()?.exportXfdf();
        if (xfdf) await fetch("/api/comments", { method: "PUT", body: xfdf });
      }}
      style={{ height: "80vh" }}
    />
  );
}

    How it works

    Embed a PDF viewer in your web app in three steps

    The viewer is a WebAssembly app in an iframe on your own origin. A small typed wrapper talks to it, so your code stays simple and your page stays isolated.

    1. 1

      Install

      Add the package to your app.

      npm install @mecorelabs/free-pdf-sdk
    2. 2

      Serve the viewer

      Copy the viewer files into a folder your site serves, on the same origin.

      npx @mecorelabs/free-pdf-sdk copy-viewer public/free-pdf-sdk
    3. 3

      Mount it

      Give an element a height and initialise it with a mode and a document.

      FreePdf.init(el, { baseUrl, mode })

    FAQ

    Questions about Free PDF SDK

    Is Free PDF SDK free for commercial use?

    Yes. Free PDF SDK is licensed MIT OR Apache-2.0, at your option, including commercial use and white-labelling. It is built on the open-source pdfcraft engine; keep the NOTICE and third-party/ files that copy-viewer copies next to the viewer when you deploy. See licences and notices.

    Does it need a server? Where do my documents go?

    There is no server component. The viewer opens the PDF with WebAssembly in the browser, and saved PDFs and XFDF comments go to your own code. The SDK sends no documents, comments, passwords or telemetry to any server.

    Which frameworks does it support?

    React and Next.js, Vue and Nuxt, Angular, Svelte and SvelteKit, a Web Component for any page, and plain JavaScript.

    Can I load it from a CDN?

    No. You serve the viewer files from your own origin, copied there with npx @mecorelabs/free-pdf-sdk copy-viewer. See Hosting and security.

    Does it work on phones and tablets?

    Yes, in mobile browsers that support WebAssembly and WebGL. The first visit downloads about 10 MB (compressed), which is then cached. More answers are in the FAQ.
